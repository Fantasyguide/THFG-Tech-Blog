# 本地文章 → 幻想指南编辑器

本地 Markdown 是正文来源。转换器生成带样式的 HTML 源码，复制到网站的代码编辑区，再由用户点击“预览”。**工作流不保存、不上传、不发布网站文章。发布始终由用户亲自完成。**

## 样式参考

`style-demos/index.html` 提供六种博客主题的独立中文小样：PaperMod、NexT、Ghost Casper、Bear、Chirpy 和 Tufte。它们使用同一篇原创短示例，各自附有原主题链接。详见 [样式小样说明](style-demos/README.md)，运行 `npm run styles` 可以重新生成。

## 日常使用

需要 Node.js 22 或更高版本。第一次使用运行 `npm ci`，当前机器已安装依赖。

```sh
# 转换所有文章目录中的 Markdown
npm run build

# 只转换一篇，或一个文件夹
npm run build -- obs/obs.md
npm run build -- obs
```

以 `obs/obs.md` 为例，输出为：

| 文件 | 用途 |
| --- | --- |
| `dist/obs/obs.paste.html` | 要粘贴到网站编辑器的全部源码 |
| `dist/obs/obs.preview.html` | 可直接在浏览器打开的预览，带复制按钮 |
| `dist/obs/obs.images.json` | 图片原路径、站内路径、本地预览路径、替代说明与图注清单 |
| `dist/obs/obs.assets/` | 本地预览使用的图片副本，搬动预览文件时需一起保留 |
| `dist/index.html` | 本次转换的文章入口 |

操作顺序：

1. 修改原始 `.md`，运行转换命令。
2. 打开生成的 `.preview.html`，检查正文，也可以展开目录和折叠说明。
3. 点击“复制到网站编辑器”。复制的是 HTML **源码文本**，不是浏览器里的富文本选区。若自动复制不可用，点击“查看源码”，全选后复制。
4. 在 [OBS 文章编辑页](https://fantasyguide.cn/articles/tech_obs/edit)的代码编辑区粘贴源码。替换已有内容前，先备份编辑器里的原文。
5. 点击网站的“预览”检查。保存和发布由用户根据需要亲自操作。

修改生成文件会在下次转换时被覆盖。正文修改写在原始 Markdown；排版修改写在 `styles/article.css`。

## 作者与图片地址

作者和邮箱直接写在 Markdown 的标题、可选副标题之后，例如 `obs/obs.md` 中：

```html
<p class="byline">
  <span>作者：卡诺热机之梦</span>
  <span>邮箱：<a href="mailto:390177665@qq.com">390177665@qq.com</a></span>
  <span>写于 <time datetime="2026-11-14">2026 年 11 月 14 日</time></span>
</p>
```

转换器将这个段落放在文章标题区；姓名、邮箱、写作日期都从 Markdown 读取。修改联系方式时同步修改链接中的地址；修改日期时同步修改 `datetime` 和显示文字，重新构建不会自动变更日期。无需署名时可以省略这个段落。

图片目录放在 Markdown 旁同名的 `.article.json` 配置中。例如 `obs/obs.article.json`：

```json
{
  "imageBase": "/backend/file/article_file/tech_obs/"
}
```

省略 `imageBase` 时，图片继续使用编号占位块。

Markdown 保留 `images/vga.jpg` 等本地路径。转换后，粘贴源码中的图片及对应原图链接使用 `/backend/file/article_file/tech_obs/vga.jpg`。按照网站上传后的命名，文件名中的空格（含原路径中的 `%20`）统一替换为下划线，例如 `obs ui.png` → `obs_ui.png`、`3.5mm%20audio.jpg` → `3.5mm_audio.jpg`；大小写保持不变，例如 `typeC.jpg`。其余字符按 URL 规则编码，不会重复编码。图片须由用户按这些名称放到网站对应目录，本工具只替换地址，不上传文件。

本地预览读取 `.assets/` 中按目标文件名生成的图片副本，原始图片无需重命名；“复制到网站编辑器”始终复制站内路径，不复制本地路径或图片数据。原路径与目标地址的对应关系保存在 `.images.json`。若不同原图转换后得到相同的目标文件名，构建会报错，避免覆盖。

粗体的结尾标点应放在标记外，例如 `**但是**！HDMI`、`**接下来我们测试音频连接方式**。如果……`。如果写成 `**但是！**HDMI`，标点紧邻结束标记，后面又直接接正文，标准 Markdown 解析器会将这对 `**` 当成普通字符。已调整本文 5 处标记，保留原文字句。

## 图片与排版

- 配置站内路径时保留图片、尺寸和图注；未配置时生成编号占位。粘贴源码不嵌入本地图片数据，不包含上传操作。
- 保留原文、多级标题、粗体、斜体、删除线、列表、引用块（包括列表内的引用）、表格、链接、代码、快捷键，以及 `<details>` 的默认展开状态。
- 目录收录二至六级标题，按实际层级嵌套，使用 `3 → 3.7 → 3.7.1` 这样的编号；附有返回开头链接、估计字数与阅读时间。
- 正文区域可用宽度达到 960px 时，目录在正文右侧常驻，随页面滚动保持可见；长目录可独立滚动。宽度不足时改为正文顶部的折叠目录。根据文章容器宽度判断，适应网站自身的侧栏。
- 使用所选 PaperMod 小样的白底、黑灰配色与无衬线标题。正文和目录整体带 1px 灰色圆角边框；带侧栏时整体最大宽度为 1114px，正文最大宽度为 800px；单栏时最大宽度为 850px（含左右各 24px 留白和边框）。
- 桌面正文为 17px、1.8 倍行距；手机为 16px、1.9 倍行距。侧栏目录使用缩进与细线区分层级，手机目录和折叠说明使用浅灰底，代码块使用深色底，表格在自身容器内横向滚动。
- 覆盖正文中的零散行内样式，统一阅读体验；标题层级依靠字号、字重和留白区分。
- 单独居中的段落在 Markdown 中写作 `<p class="fg-center">内容</p>`；其中粗体使用 `<strong>内容</strong>`。
- 右对齐、灰色段落写作 `<p class="fg-right fg-muted">内容</p>`；`fg-right` 和 `fg-muted` 也可单独使用。
- 不执行 Markdown 里的脚本、表单或事件属性。数学公式目前没有额外渲染支持。
- 新文章可直接放在任意文章子目录下；批量转换跳过隐藏目录、依赖、生成目录、工具目录以及 README/AGENTS。

## 预览服务（可选）

生成的预览文件可以直接打开；也可以启动仅本机可访问的静态服务。先确认端口空闲，不要终止其他服务腾位置。

```sh
npm run preview -- --host 127.0.0.1 --port 3100
```

访问 `http://localhost:3100/obs/obs.preview.html`。localhost 指运行服务的机器。通过 SSH 在另一台机器使用时，可在客户端建立自己选择的本地端口转发；本工作流默认不对局域网公开未发布内容。

服务只接受 GET/HEAD，仅提供 `dist` 目录，没有网站接口代理或写入功能。修改 Markdown 后重新运行构建并刷新预览页即可。

## 检查与网站兼容性

```sh
npm test

# 首次在没有浏览器的机器上进行视觉检查时
npx playwright install chromium
npm run check:visual
```

可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已有 Chromium。截图环境需要可用的中文字体。视觉检查会阻断所有网络请求；测试结果和截图位于 `dist/checks`。

2026-11-13 检查了网站公开前端与 [第十七届文章](https://fantasyguide.cn/articles/fantasyguide_17)、[第三只眼文章](https://fantasyguide.cn/articles/satori_3rd_eye)。确认网站使用 Monaco 源码编辑器，正文经 Markdown、HTML 清理和 CSS 处理后渲染。

本次额外下载了公开的渲染代码与样式，在本地移除网站启动逻辑后，离线验证生成内容。没有读取已登录标签页，也没有在网站编辑器内粘贴、保存或发布。当前机器的公开资源快照保留在 `dist/checks/site-snapshot`，可再次检查：

```sh
npm run check:visual -- --site-snapshot=dist/checks/site-snapshot
```

快照不进入版本控制。此检查依赖已核验的前端构建结构；网站更新后应重新读取公开资源并审查提取位置，不能把旧快照视为实时网站验证。

样式放在一个 HTML 包装块内，每条规则都限定在文章区域；针对包含本篇文章的宿主容器修正宽度和手机边距。这样兼容网站对独立 `<style>` 块的选择器处理，也避免影响其他文章。文章末尾使用普通容器，以避开网站针对 `footer` 的全局固定定位规则。

本次通过 13 项转换检查，并在本地预览及网站渲染器本地副本中验证了 1440、1024、768、390、320px 宽度。目录检查涵盖 23 个条目的层级与编号、右侧吸顶、不遮挡正文、短屏时独立滚动到底部、手机折叠，以及深层标题跳转。另检查了整体边框、13 处引用块、5 个折叠区、16 张图片、Markdown 中的作者与邮箱、修复后的粗体和复制失败时的手动回退。网站渲染器的离线视觉检查使用本地图片数据，不请求线上图片，也不代表已确认图片上传完成。
